### 7. 线上监控与漂移检测

**模型上线后会变差,即使代码一行没改。** 因为世界在变:

|类型|含义|例子|
|---|---|---|
|**数据漂移**|输入的分布变了|原来评论大多是酒店,现在涌入大量餐厅评论|
|**概念漂移**|输入和标签的关系变了|网络用语变化,同一个词的情感色彩不同了|
|**标签漂移**|类别比例变了|疫情期间差评突然暴增|

难点在于:线上通常**拿不到真实标签**(用户不会告诉你预测对没对),所以只能监控**输入分布和输出分布**这些代理信号。

#### 漂移指标:PSI 和 KS 检验

python

```python
import json

import numpy as np
from scipy.stats import ks_2samp


def psi(reference, current, bins=10):
    """群体稳定性指数。把参考数据按分位数切箱,比较两份数据落在各箱的比例"""
    edges = np.unique(np.quantile(reference, np.linspace(0, 1, bins + 1)))
    edges[0], edges[-1] = -np.inf, np.inf
    ref = np.histogram(reference, edges)[0] / len(reference)
    cur = np.histogram(current, edges)[0] / len(current)
    ref, cur = np.clip(ref, 1e-6, None), np.clip(cur, 1e-6, None)     # 避免 log(0)
    return float(np.sum((cur - ref) * np.log(cur / ref)))


def read_log(path):
    rows = [json.loads(line) for line in open(path, encoding="utf-8")]
    return {k: np.array([r[k] for r in rows]) for k in rows[0]}


def drift_report(ref, cur):
    print(f"{'指标':<14}{'PSI':>8}{'KS p值':>10}   判断")
    for name in ["text_len", "confidence"]:
        p = psi(ref[name], cur[name])
        ks_p = ks_2samp(ref[name], cur[name]).pvalue
        verdict = "稳定" if p < 0.1 else "轻微漂移,需关注" if p < 0.25 else "显著漂移,需排查"
        print(f"{name:<14}{p:>8.3f}{ks_p:>10.4f}   {verdict}")
    pos_ref, pos_cur = ref["label_id"].mean(), cur["label_id"].mean()
    print(f"{'正面占比':<12}{pos_ref:>8.2%} -> {pos_cur:.2%}")
    print(f"{'低置信度占比':<10}{(ref['confidence']<0.7).mean():>8.2%} -> {(cur['confidence']<0.7).mean():.2%}")
```

**PSI 的经验阈值**(行业通用的经验规则,不是数学定理):小于 0.1 稳定,0.1~0.25 需要关注,大于 0.25 通常要排查原因。

**KS 检验的陷阱:** 样本量很大时,哪怕分布只有微不足道的差异,p 值也会小到显著。所以 p 值小**不等于**需要行动,要结合 PSI 的大小和业务判断。

#### 用模拟数据演示

你的服务刚上线,还没有足够的真实日志,先模拟一次"上线后用户群体悄悄变了":

python

```python
rng = np.random.default_rng(0)

def fake_log(n, len_mean, pos_rate, conf_a, conf_b):
    return {
        "text_len": np.clip(rng.normal(len_mean, 40, n), 5, 600).astype(int),
        "label_id": (rng.random(n) < pos_rate).astype(int),
        "confidence": rng.beta(conf_a, conf_b, n),
    }

reference = fake_log(2000, len_mean=110, pos_rate=0.5, conf_a=8, conf_b=1.2)   # 上线初期

print("=== 一周后(没有变化) ===")
drift_report(reference, fake_log(1000, 110, 0.5, 8, 1.2))

print("\n=== 一个月后(评论变短、负面变多、模型更没把握) ===")
drift_report(reference, fake_log(1000, 55, 0.3, 4, 2))
```

跑一下,你会看到第一份报告都显示稳定,第二份多项指标亮红灯。**真实服务里,这个脚本应该定时运行**(比如每天一次),指标超阈值就发告警。

#### 发现漂移之后怎么办

1. **先排查是不是数据管道的 bug**(前端改了字段、编码出了问题),很多"漂移"其实是工程问题
2. 抽样人工标注一批最近的数据,**测量真实准确率**,确认模型是不是真的变差了
3. 确认变差后,用新数据重新训练或微调,走评估、对比、灰度发布的流程
4. **永远保留回滚能力:** 新版本表现更差时,能立刻切回旧版本。这就是前面做模型哈希和版本记录的意义
