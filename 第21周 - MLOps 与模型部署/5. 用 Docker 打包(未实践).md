### 5. 用 Docker 打包

Docker 解决"在我电脑上能跑,到别处就不行"的问题:把代码、依赖、系统环境一起打成一个镜像。

新建 `requirements.txt`:

```
fastapi
uvicorn[standard]
transformers
pydantic>=2
```

新建 `Dockerfile`:

dockerfile

```dockerfile
FROM python:3.12-slim

WORKDIR /app

# 先装依赖再拷代码:依赖不变时,Docker 能复用缓存层,重新构建很快
RUN pip install --no-cache-dir torch --index-url https://download.pytorch.org/whl/cpu
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY app.py .
COPY chn-sentiment-final ./model

# 不要用 root 运行服务
RUN useradd -m appuser && chown -R appuser /app
USER appuser

ENV MODEL_DIR=/app/model LOG_PATH=/tmp/predictions.jsonl
EXPOSE 8000

HEALTHCHECK --interval=30s --timeout=5s --start-period=40s \
  CMD python -c "import urllib.request as u; u.urlopen('http://127.0.0.1:8000/health')" || exit 1

CMD ["uvicorn", "app:app", "--host", "0.0.0.0", "--port", "8000"]
```

新建 `.dockerignore`:

```
__pycache__
*.pyc
.venv
data
mlruns
mlflow.db
predictions.jsonl
chn-sentiment/
imdb-distilbert/
*.pt
```

(这里排除的是训练过程中产生的 checkpoint 目录,只保留最终模型 `chn-sentiment-final`,否则镜像会大好几倍。)

构建与运行:

powershell

```powershell
docker build -t sentiment-api:1.0 .
docker run --rm -p 8000:8000 sentiment-api:1.0
```

然后用前面的 Python 客户端再调一遍,应该一样能用。

**关于你的显卡:** 这个镜像用的是 **CPU 版 PyTorch**。AMD 显卡在 Windows 的 Docker 容器里直通 GPU 目前不是一件省心的事,而一个 base 规模的分类模型用 CPU 推理完全够用。真要在容器里用 AMD GPU,通常是在 Linux 服务器上做,具体方式以 AMD 官方文档为准。

**没装 Docker 也不影响:** 它是选做。理解"为什么要容器化"和"Dockerfile 每一行在干什么",比亲自跑通更重要。
